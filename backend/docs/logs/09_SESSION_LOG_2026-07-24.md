2. All money-related logic isolated in a dedicated `payments` module (Sprint 4)
3. Large files go to object storage; database stores only metadata URLs
4. All mutations write to an immutable audit log

## 3. Issues Encountered and Resolutions

### Issue 1: Backend Dependencies — Deprecated `uuid` + Security Vulnerabilities

**Problem:**
```
npm warn deprecated uuid@10.0.0: uuid@10 and below is no longer supported.
6 vulnerabilities (3 moderate, 2 high, 1 critical)
```

**Root Cause:**
- `uuid` v10 deprecated. Code already used Node.js native `crypto`, so `uuid` was unused.
- `nodemailer` v6.9.14 had multiple HIGH severity SMTP injection CVEs.
- `vitest` v1.6.0 pulled in vulnerable `esbuild`.

**Resolution:**
```
# Removed unused packages
- "uuid": "^10.0.0"
- "@types/uuid": "^9.0.8"

# Updated vulnerable packages
- "nodemailer": "^6.9.14" → "^9.0.3"
- "vitest": "^1.6.0" → "^3.2.5"

# Reinstalled
rm -rf node_modules package-lock.json && npm install

# Result: found 0 vulnerabilities
```

### Issue 2: Prisma Migration — PostgreSQL Port Conflict on Windows

**Problem:**
```
Error: P1000: Authentication failed against database server at `localhost`,
the provided database credentials for `elms` are not valid.
```

**Root Cause:** Windows already had a native PostgreSQL service (`postgres.exe`) running on port 5432. Docker tried to bind to the same port, but traffic was going to the native instance which didn't have the `elms` user/database.

**Diagnosis Steps:**
1. `docker ps` → container running, port `5432:5432`
2. `netstat -ano | findstr 5432` → two processes listening (native postgres + Docker)
3. Native PostgreSQL (PID 6760) owned port 5432
4. Attempted to change Docker to port 5433, but a SECOND native PostgreSQL (PID 6728) was also running on 5433

**Resolution:**
```yaml
# docker-compose.yml
ports:
  - "5434:5432"  # Docker host port 5434 → container port 5432
```

```env
# .env
DATABASE_URL=postgresql://elms:elms_secret@127.0.0.1:5434/elms_db?schema=public
```

**Key Lesson:** On Windows, check `netstat -ano` and `tasklist` before assuming port availability.

### Issue 3: Nodemailer Import Error After Upgrade to v9

**Problem:**
```
TypeError: import_nodemailer.default.createTransporter is not a function
```

**Root Cause:**
1. Typo: `createTransporter` should be `createTransport`
2. Import style: `import nodemailer from "nodemailer"` doesn't work well with nodemailer v9 in tsx/CommonJS hybrid mode

**Resolution:**
```typescript
// Before
import nodemailer from "nodemailer";
const transporter = nodemailer.createTransporter({...});

// After
import * as nodemailer from "nodemailer";
const transporter = nodemailer.createTransport({...});
```

### Issue 5: Frontend Build Error — Corrupted JSX in App.tsx

**Problem:**
```
X [ERROR] Syntax error "c"
src/App.tsx:42:3:
  42 │  003cProtectedRoute>
```

**Root Cause:** The Write tool encoded `<` as `003c` (HTML entity encoding) on line 42 during file creation. This only affected that one line.

**Resolution:**
```tsx
// Before
003cProtectedRoute>

// After
<ProtectedRoute>
```
